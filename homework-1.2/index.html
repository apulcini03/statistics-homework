Theoretical Background

Overview: Ethereum Wallet Derivation

Ethereum wallets combine several cryptographic standards and primitives to derive addresses from a mnemonic recovery phrase. Each component has a distinct purpose: key management, deterministic derivation, public-key cryptography, hashing or error detection.

BIP-39 — Mnemonic and Seed Generation

BIP-39 defines how random entropy is encoded into a human-readable mnemonic sentence, including checksum information.

The mnemonic, together with an optional passphrase, is converted into a 512-bit seed using PBKDF2-HMAC-SHA512 with 2048 iterations.

The mnemonic represents secret recovery information. The resulting seed is deterministic and can be used to reconstruct the wallet.

Mnemonic Checksum and Entropy

A typical 12-word BIP-39 mnemonic encodes 128 bits of initial entropy and 4 checksum bits.

The checksum is obtained from the first 4 bits of SHA-256 applied to the original entropy. The resulting 132 bits are divided into 12 groups of 11 bits, each selecting one word from a 2048-word list.

This checksum helps detect invalid mnemonic phrases, but it does not provide authentication or protect against deliberate manipulation.

The subsequent 512-bit seed is derived using PBKDF2-HMAC-SHA512 with 2048 iterations. The mnemonic checksum and seed derivation are separate operations.

BIP-32 — Hierarchical Deterministic Derivation

BIP-32 defines hierarchical deterministic (HD) wallets, allowing multiple child keys to be derived from a single master key.

The master node is derived from the seed using HMAC-SHA512 and contains a private key and a chain code. Child keys are then derived through a hierarchical key derivation process.

The same seed and derivation path always produce the same derived key, allowing wallet recovery.

BIP-44 — Standard Derivation Paths

BIP-44 defines a standardized organization for HD wallet derivation paths:

m / purpose' / coin_type' / account' / change / address_index

A common Ethereum path is m/44'/60'/0'/0/0, where 44' identifies BIP-44 and 60' identifies Ethereum.

The apostrophe indicates hardened derivation. Changing the final address index allows multiple addresses to be derived from the same seed. BIP-44 defines path conventions, not a new cryptographic algorithm.

secp256k1 — Public-Key Cryptography

secp256k1 is the elliptic curve used in Ethereum's traditional externally owned account cryptography.

A private key k is a scalar, while the corresponding public key is a curve point:

Q = kG

Here, G is the fixed generator point. Computing the public key is efficient, whereas recovering the private scalar from the public point is computationally difficult for real cryptographic parameters.

Ethereum traditionally uses ECDSA over secp256k1 to authorize transactions through digital signatures.

Keccak-256 — Ethereum Address Hashing

Keccak-256 is a cryptographic hash function producing a 256-bit digest.

To derive an Ethereum address, the 64 bytes representing the X and Y coordinates of the uncompressed public key are hashed using Keccak-256, excluding the 04 prefix.

The last 20 bytes of the digest form the 160-bit Ethereum address.

Ethereum uses Keccak-256, which is not identical to NIST SHA3-256. Although both share the Keccak sponge construction, they use different domain-separation conventions and produce different digests.

EIP-55 — Address Checksum Encoding

EIP-55 defines a mixed-case hexadecimal representation for Ethereum addresses.

The capitalization of hexadecimal letters is determined using Keccak-256 applied to the lowercase address text.

This provides additional error detection without changing the underlying 20-byte address. It is not a digital signature or an authentication mechanism.

Key Generation vs Key Derivation

Key generation introduces new secret randomness, such as the entropy used to create a BIP-39 mnemonic.

Key derivation deterministically computes keys from existing secret material. BIP-32 performs this role using the seed and a hierarchical derivation path.

Hashing, Checksums and Encoding

Hashing transforms input data into a fixed-length digest. Keccak-256 performs this function during address derivation.

A checksum helps detect accidental errors, while encoding specifies how information is represented or displayed.

EIP-55 combines checksum information with mixed-case hexadecimal encoding. These operations serve purposes different from asymmetric cryptography and key derivation.

Why Multiple Cryptographic Primitives?

A single cryptographic algorithm cannot efficiently provide all the different functions required by an Ethereum wallet.

BIP-39 supports mnemonic recovery, BIP-32 and BIP-44 organize deterministic key derivation, secp256k1 provides the private/public key relationship and digital signatures, Keccak-256 provides hashing, and EIP-55 supports address error detection.

Combining specialized components enables reproducible wallet recovery, multiple derived addresses, transaction authorization and more reliable address representation.

Historical Timeline

Evolution of Cryptographic Technologies

Ethereum wallets combine technologies developed during different periods of cryptographic research. The following timeline highlights important milestones in their historical development.

1977

RSA — Public-Key Cryptography

Rivest, Shamir and Adleman introduced RSA, one of the earliest widely adopted public-key cryptosystems. It demonstrated how public and private keys could support secure communication and digital signatures.

2001

SHA-2 / SHA-512

The SHA-2 family was developed by the NSA and standardized by NIST in the early 2000s. SHA-512 produces a 512-bit digest and is used within HMAC and PBKDF2 for BIP-39 seed derivation.

2012

BIP-32 — Hierarchical Deterministic Wallets

BIP-32 introduced a hierarchical structure for deriving multiple cryptographic keys from a single master seed, simplifying backup and wallet recovery.

2013

BIP-39 — Mnemonic Recovery Phrases

BIP-39 introduced a standard approach for encoding wallet entropy as a human-readable mnemonic and deriving a seed from it.

2014

BIP-44 — Multi-Account HD Wallets

BIP-44 defined a common derivation-path structure supporting different coins, accounts and address indices.

2015

SHA-3 — NIST Standardization

NIST standardized the SHA-3 family based on Keccak. Ethereum uses Keccak-256, which differs from standardized SHA3-256 because of domain-separation conventions.

2016

EIP-55 — Mixed-Case Address Checksum

EIP-55 proposed a mixed-case hexadecimal encoding for Ethereum addresses, providing additional detection of transcription errors without altering the underlying address.

The dates identify major publications or standardization milestones, rather than the invention dates of every underlying cryptographic technique.

Results and Conclusions

Deterministic Wallet Derivation

The experiment demonstrates that a single BIP-39 mnemonic can deterministically generate an entire hierarchy of Ethereum keys and addresses.

Using the same mnemonic and derivation path always produces the same private key, public key and Ethereum address. Changing the final BIP-44 address index generates a different derived key while preserving the original seed.

Statistical Results — 20 Ethereum Addresses

The experiment analyzed 20 addresses obtained from consecutive derivation indices. Each address contains 160 bits, for a total of 3,200 bits.

The observed distribution contained 1,588 zero bits and 1,612 one bits, corresponding to 49.625% zeros and 50.375% ones.

The observed proportions are close to the theoretical 50/50 distribution expected under an ideal model of uniformly random bits.

Hamming Distance Analysis

The 20 addresses produced 19 consecutive address comparisons. Their mean Hamming distance was 79.74 bits out of 160, with a minimum of 69 and a maximum of 91.

Under a model of independent uniformly random 160-bit addresses, the expected Hamming distance is 80 bits, with standard deviation approximately 6.32 bits.

The observed mean is close to this theoretical reference. However, the experiment uses only a small deterministic sample, so it does not prove statistical independence, unpredictability or cryptographic security.

Furthermore, changing a derivation index does not correspond to changing exactly one bit of the mnemonic or seed. Therefore, this experiment should not be interpreted as a formal test of the avalanche effect.

Hash Function Comparison

Hashing the same input with Keccak-256, SHA3-256 and SHA-512 produces different digests.

Keccak-256 and SHA3-256 produce 256-bit outputs but differ in domain separation and padding conventions. For the test message "abc", their outputs differ in 138 out of 256 bits.

SHA-512 belongs to the SHA-2 family and produces a 512-bit digest. In the wallet pipeline, HMAC-SHA512 is used within key derivation, while Keccak-256 is used for Ethereum address generation.

The observed Hamming distance between Keccak-256 and SHA3-256 is a descriptive comparison of two outputs, not a security comparison between the algorithms.

Why Different Cryptographic Primitives?

Ethereum wallets combine multiple cryptographic techniques because each solves a different problem.

BIP-39 provides a mnemonic representation and seed derivation mechanism. BIP-32 enables hierarchical deterministic key derivation, while BIP-44 standardizes the organization of derivation paths.

secp256k1 establishes the mathematical relationship between private and public keys and supports digital signatures. Keccak-256 provides cryptographic hashing for address derivation. EIP-55 adds error-detection information through mixed-case hexadecimal encoding.

These operations are complementary: hashing cannot replace asymmetric digital signatures, checksum encoding cannot replace cryptographic security, and key derivation cannot replace secure random entropy generation.

Keccak-256 Avalanche Effect Experiment

An additional experiment investigated the diffusion properties of Keccak-256 by modifying exactly one bit of a fixed 256-bit input.

In a sample of 200 trials, 132 distinct input-bit positions were tested. The observed mean Hamming distance was 128.63 out of 256 output bits, compared with a theoretical mean of 128.

The observed standard deviation was 7.96, close to the ideal theoretical value of 8. The observed distances ranged from 105 to 151 bits.

These observations are consistent with the diffusion behaviour expected from a cryptographic hash function: changing one input bit typically changes approximately half of the output bits.

Since input-bit positions were selected with replacement, some trials repeated the same modification. Consequently, the observations are not all independent. The experiment illustrates avalanche-like behaviour but does not prove cryptographic security or the strict avalanche criterion.

Final Conclusion

The Ethereum wallet pipeline illustrates how cryptographic standards and primitives work together to transform secret recovery information into deterministic public addresses.

The statistical exploration showed approximately balanced address bits and Hamming distances close to the ideal random-output reference. These observations are useful for understanding output distributions, but they are not sufficient to establish cryptographic security.

The main lesson is that secure wallet operation depends on the correct use of specialized cryptographic components, rather than a single algorithm performing every function.
