Theoretical Background

Overview: Ethereum Wallet Derivation

Ethereum wallets combine several cryptographic standards and primitives to derive addresses from a mnemonic recovery phrase. Each component has a distinct purpose: key management, deterministic derivation, public-key cryptography, hashing or error detection.

BIP-39 — Mnemonic and Seed Generation

BIP-39 defines how random entropy is encoded into a human-readable mnemonic sentence, including checksum information.

The mnemonic, together with an optional passphrase, is converted into a 512-bit seed using PBKDF2-HMAC-SHA512 with 2048 iterations.

The mnemonic represents secret recovery information. The resulting seed is deterministic and can be used to reconstruct the wallet.

BIP-32 — Hierarchical Deterministic Derivation

BIP-32 defines hierarchical deterministic (HD) wallets, allowing multiple child keys to be derived from a single master key.

The master node is derived from the seed using HMAC-SHA512 and contains a private key and a chain code. Child keys are then derived through a hierarchical key derivation process.

The same seed and derivation path always produce the same derived key, allowing wallet recovery.

BIP-44 — Standard Derivation Paths

BIP-44 defines a standardized organization for HD wallet derivation paths:

m / purpose' / coin_type' / account' / change / address_index

A common Ethereum path is m/44'/60'/0'/0/0, where 44' identifies BIP-44 and 60' identifies Ethereum.

The apostrophe indicates hardened derivation. Changing the final address index allows multiple addresses to be derived from the same seed. BIP-44 defines path conventions, not a new cryptographic algorithm.

secp256k1 — Public-Key Cryptography

secp256k1 is the elliptic curve used in Ethereum's traditional externally owned account cryptography.

A private key k is a scalar, while the corresponding public key is a curve point:

Q = kG

Here, G is the fixed generator point. Computing the public key is efficient, whereas recovering the private scalar from the public point is computationally difficult for real cryptographic parameters.

Ethereum traditionally uses ECDSA over secp256k1 to authorize transactions through digital signatures.

Keccak-256 — Ethereum Address Hashing

Keccak-256 is a cryptographic hash function producing a 256-bit digest.

To derive an Ethereum address, the 64 bytes representing the X and Y coordinates of the uncompressed public key are hashed using Keccak-256, excluding the 04 prefix.

The last 20 bytes of the digest form the 160-bit Ethereum address.

Ethereum uses Keccak-256, which is not identical to NIST SHA3-256. Although both share the Keccak sponge construction, they use different domain-separation conventions and produce different digests.

EIP-55 — Address Checksum Encoding

EIP-55 defines a mixed-case hexadecimal representation for Ethereum addresses.

The capitalization of hexadecimal letters is determined using Keccak-256 applied to the lowercase address text.

This provides additional error detection without changing the underlying 20-byte address. It is not a digital signature or an authentication mechanism.

Key Generation vs Key Derivation

Key generation introduces new secret randomness, such as the entropy used to create a BIP-39 mnemonic.

Key derivation deterministically computes keys from existing secret material. BIP-32 performs this role using the seed and a hierarchical derivation path.

Hashing, Checksums and Encoding

Hashing transforms input data into a fixed-length digest. Keccak-256 performs this function during address derivation.

A checksum helps detect accidental errors, while encoding specifies how information is represented or displayed.

EIP-55 combines checksum information with mixed-case hexadecimal encoding. These operations serve purposes different from asymmetric cryptography and key derivation.

Why Multiple Cryptographic Primitives?

A single cryptographic algorithm cannot efficiently provide all the different functions required by an Ethereum wallet.

BIP-39 supports mnemonic recovery, BIP-32 and BIP-44 organize deterministic key derivation, secp256k1 provides the private/public key relationship and digital signatures, Keccak-256 provides hashing, and EIP-55 supports address error detection.

Combining specialized components enables reproducible wallet recovery, multiple derived addresses, transaction authorization and more reliable address representation.
