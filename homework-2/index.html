Assignment Overview

Objective

This homework compares a toy elliptic-curve-based encryption scheme with the classical Caesar cipher.

The study explores encryption and decryption procedures, the role of cryptographic keys, key-space sizes, and statistical properties.

It also investigates two attacks: statistical key recovery against Caesar-encrypted text and exhaustive private-key search against a deliberately restricted ECC key space.

Part 1 — ECC Encryption and Decryption

Toy ECC-Based Hybrid Encryption

This demonstration uses the real secp256k1 elliptic curve with an intentionally restricted recipient private-key space.

Elliptic-curve Diffie-Hellman (ECDH) establishes a shared secret. HKDF-SHA256 derives a symmetric encryption key, and AES-256-GCM encrypts the message.

Step 1 — Recipient Key Generation

The private key is a scalar d, and the public key is computed as Q = dG. For this experiment, the recipient private key is limited to 1–1000.

Step 2 — Encrypt a Message

The sender generates a fresh ephemeral key pair, computes an ECDH shared secret using the recipient's public key, and encrypts the message.

Step 3 — Decrypt the Message

The recipient uses the private key and the sender's ephemeral public key to reconstruct the same shared secret and symmetric key.

Role of the Cryptographic Keys

Recipient private key: Secret scalar used to decrypt messages. In this toy scheme, its small key space makes exhaustive recovery feasible.

Recipient public key: Public curve point used by the sender to establish a shared secret.

Ephemeral private key: Fresh randomly generated sender secret used for one encryption operation.

Ephemeral public key: Included with the ciphertext so that the recipient can reconstruct the shared secret.

AES key: A 256-bit symmetric key derived from ECDH using HKDF-SHA256. It encrypts and decrypts the actual message.

Part 2 — Caesar Cipher

Classical Substitution Cipher

The Caesar cipher is a symmetric substitution cipher in which each letter is shifted by a fixed number of positions in the alphabet.

Encryption: E(x) = (x + k) mod 26

Decryption: D(y) = (y - k) mod 26

Step 1 — Select the Message and Key

The key determines how many positions each letter moves in the English alphabet. Spaces, numbers and punctuation remain unchanged.

Step 2 — Encrypt the Message

Each alphabetical character is shifted forward by the selected key, with wraparound after Z.

Step 3 — Decrypt the Message

Decryption applies the inverse shift to recover the original plaintext using the same secret key.

Role of the Key

The Caesar cipher uses the same key for encryption and decryption. Its key space contains only 26 possible shifts, including the identity transformation when k = 0.

Because the key space is extremely small, an attacker can test every candidate. Furthermore, the substitution preserves the frequency distribution of letters, allowing statistical cryptanalysis.

The Caesar cipher is historically significant but provides no practical cryptographic security.

Part 3 — Cryptosystem Comparison

ECC-Based Encryption vs Caesar Cipher

Both schemes transform plaintext into ciphertext and allow the original message to be recovered using appropriate key material. However, their underlying mathematical constructions, key management and security properties are fundamentally different.

Encryption and Decryption Procedures

The Caesar cipher applies a fixed substitution to each letter independently. Encryption and decryption require only modular arithmetic, and the same shift key is used in both directions.

The ECC-based experiment uses asymmetric elliptic-curve keys to establish a shared secret. The message itself is encrypted symmetrically with AES-GCM using a key derived via HKDF. Unlike Caesar, the resulting ciphertext also contains an authentication tag.

Comparison of Key Spaces

Caesar has only 26 possible shifts, one of which is the identity transformation. Consequently, all keys can be tested with negligible computational effort.

In our toy ECC-based scheme, the recipient private key is restricted to 1000 values. This makes exhaustive private-key recovery practical despite using the real secp256k1 curve.

A correctly generated secp256k1 private key normally belongs to a much larger space of approximately 2^256 possible values. Searching that space exhaustively is infeasible with currently known practical methods.

Statistical Properties

Caesar encryption preserves the relative frequencies of individual letters because each plaintext letter is consistently mapped to exactly one ciphertext letter.

For example, a frequent letter such as E remains frequent after encryption, although it appears under another letter. This allows an attacker to exploit the known statistical distribution of written English.

By contrast, the ECC-based hybrid scheme uses AES-GCM to encrypt the message as bytes. It does not produce a simple substitution of the original alphabet, so classical letter-frequency cryptanalysis is not directly applicable.

Security Implications

The Caesar cipher is insecure because its entire key space is tiny and its substitution preserves substantial linguistic structure.

The toy ECC-based scheme is insecure because we deliberately restrict the recipient private key to a small interval. An attacker can test candidate keys against the known public key.

The restricted key space is a weakness of this educational configuration, not an inherent weakness of secp256k1 itself. The custom hybrid scheme should not be considered a production encryption protocol.

Part 4 — Statistical Cryptanalysis

Recovering the Caesar Key Using Letter Frequencies

The Caesar cipher preserves the relative frequencies of letters, although their positions in the alphabet are shifted. This makes statistical key recovery possible.

Assuming the plaintext is English, the attack tests all 26 possible shifts and computes a chi-squared score comparing each decrypted candidate with expected English letter frequencies.

The candidate with the lowest chi-squared score is selected as the estimated key. A smaller score indicates a closer match to the English frequency model.

Step 1 — Prepare the Ciphertext

Enter an intercepted Caesar ciphertext. The attacker does not need to know the encryption key or original plaintext.

Step 2 — Compare All Candidate Keys

The algorithm tests all 26 possible shifts, evaluates their chi-squared scores and ranks the candidates from best to worst.

Part 5 — Restricted ECC Key-Space Attack

Exhaustive Private-Key Recovery

This experiment demonstrates an attack against an ECC-based encryption scheme whose recipient private key is deliberately restricted to the interval from 1 to 1000.

The attacker knows the recipient's public key Q = dG but does not know the private scalar d. By computing candidate public keys kG, the attacker can search for a matching point.

Step 1 — Attack Setup

Return to Part 1 and generate an ECC key pair, then encrypt a message. The encrypted package contains the public information required to attempt private-key recovery and decryption.

Known: Recipient public key, ephemeral public key, ciphertext, HKDF salt and AES-GCM IV.

Unknown: Recipient private key d.

Search space: 1000 possible private-key values.

Step 2 — Brute-Force Private-Key Search

The attack tests candidate private keys sequentially until a candidate public key matches the target.

Step 3 — Decrypt with the Recovered Key

Once the private key is recovered, the attacker computes the ECDH shared secret using the sender's ephemeral public key. HKDF derives the AES key needed to decrypt the ciphertext.

Security Interpretation

The attack succeeds because the private-key space contains only 1000 candidates. The weakness is caused by the artificial restriction, not by the secp256k1 curve.

With properly generated private keys covering the full secp256k1 range, exhaustive recovery becomes computationally infeasible.

This attack differs from statistical cryptanalysis of Caesar: it exploits a restricted cryptographic key space rather than the frequency distribution of plaintext letters.

The demonstration attacks only keys generated by this educational toy scheme. It is not an attack against properly configured ECC systems.

Part 6 — Attack Comparison and Security Limitations

Comparing the Two Cryptanalytic Attacks

The experiments demonstrate two different cryptanalytic approaches: statistical analysis of the Caesar cipher and exhaustive private-key recovery against restricted ECC.

Both attacks exploit weaknesses in the target cryptosystem, but they rely on different information and assumptions.

Statistical Attack Against Caesar

Caesar encryption applies the same alphabet permutation to every occurrence of a letter. Therefore, the statistical structure of the language remains observable, although the letter labels are shifted.

The chi-squared attack evaluates all 26 possible shifts and selects the candidate whose frequencies best match written English.

In our experiment, the attack recovered 236 out of 240 keys correctly. For samples containing 20 letters, the success rate was 90%, while the tested lengths from 50 to 800 letters achieved 100%.

These results depend on the chosen corpus, frequency model and sampled passages. They do not guarantee successful recovery for every English ciphertext.

Exhaustive Attack Against Restricted ECC

In the ECC experiment, the attacker knows the recipient's public key Q = dG and that the private scalar d belongs to the interval [1, 1000].

The attack computes candidate public keys kG for successive values of k and compares each point with Q.

When the matching candidate is found, the attacker obtains the private key needed to reconstruct the ECDH shared secret and decrypt the AES-GCM ciphertext.

With d = 123, the attack recovered the private key after 123 attempts and decrypted "HELLO STATISTICS".

This attack does not require knowledge of the plaintext or its language. It exploits the small private-key space rather than statistical patterns within the ciphertext.

Why Properly Configured ECC Is Different

Standard secp256k1 private keys are selected from a group whose order is approximately 2^256, rather than from only 1000 values.

Exhaustively enumerating that full key space would be computationally infeasible.

Generic algorithms for the elliptic-curve discrete logarithm problem, such as Pollard's rho, have a computational complexity on the order of 2^128 group operations for secp256k1.

This is still far beyond currently practical computational capabilities. Our successful attack therefore does not demonstrate a weakness of secp256k1 when keys are generated correctly.

Weaknesses of the Toy Scheme

The primary demonstrated weakness is the restricted recipient private-key interval. An attacker who knows this interval can enumerate every possibility.

The hybrid construction also relies on correct implementation choices: secure ephemeral-key generation, proper shared-secret handling, HKDF parameters, unique AES-GCM nonces and authenticated encryption.

The experiment uses established cryptographic components, but the overall construction is educational and has not been independently reviewed as a secure encryption protocol.

Alternative Attack Approaches

Caesar can also be broken through exhaustive testing of all 26 shifts, without relying on language statistics. Additional scoring techniques, such as bigram or trigram analysis, may improve the ranking of short plaintext candidates.

For a bounded elliptic-curve private-key interval, more advanced discrete-logarithm techniques can exploit the bounded range more efficiently than naive enumeration as the interval grows.

These alternative approaches do not change the main conclusion: the computational feasibility of an attack depends on the available information, algorithmic structure and effective size of the secret-key space.

Final Security Comparison

Caesar is fundamentally insecure because its key space is tiny and its substitution preserves recognizable language statistics.

The ECC-based demonstration is vulnerable because its recipient private-key space has deliberately been reduced.

The experiments illustrate that cryptographic security depends not only on the underlying mathematical primitive, but also on key generation, parameter selection and protocol design.

Results and Conclusions

Overview of the Experiments

This homework investigated encryption, decryption and cryptanalysis using two fundamentally different cryptographic systems: a toy ECC-based hybrid encryption scheme and the classical Caesar cipher.

Both systems successfully encrypted and decrypted the same test message, "HELLO STATISTICS", but relied on different mathematical operations and key-management mechanisms.

ECC Encryption and Decryption

The ECC demonstration used the real secp256k1 elliptic curve with a deliberately restricted recipient private-key range from 1 to 1000.

ECDH was used to establish a shared secret, HKDF-SHA256 derived an AES-256 key, and AES-GCM encrypted and authenticated the message.

The sender and recipient successfully reconstructed the same shared secret, allowing the original plaintext to be recovered.

Caesar Encryption and Decryption

The Caesar cipher encrypted the same message by shifting each alphabetical character by a fixed number of positions.

With encryption key k = 3, the message "HELLO STATISTICS" was transformed into "KHOOR VWDWLVWLFV".

Applying the inverse shift recovered the original plaintext.

Statistical Cryptanalysis Results

The Caesar key-recovery algorithm tested all 26 possible shifts and ranked the candidate plaintexts using a chi-squared comparison with expected English letter frequencies.

In the initial experiment, the algorithm correctly recovered the encryption key k = 3 from a ciphertext containing 194 alphabetical characters.

Effect of Ciphertext Length

A second experiment evaluated the statistical attack using ciphertexts of 20, 50, 100, 200, 400 and 800 alphabetical characters.

Forty trials were performed for each length, resulting in 240 attacks. The correct key was recovered in 236 cases, corresponding to an overall success rate of 98.33%.

For 20-character ciphertexts, the success rate was 90%. For the tested lengths from 50 to 800 characters, the observed success rate was 100%.

These results illustrate how longer texts can improve the reliability of letter-frequency analysis. However, they depend on the selected English corpus, the frequency model and the sampled passages.

In particular, the experiment used a fixed corpus and a reproducible pseudo-random sequence. Its results should not be interpreted as universal success probabilities.

Restricted ECC Private-Key Attack

The ECC attack exploited the intentionally restricted recipient private-key interval [1, 1000].

By computing candidate public keys kG and comparing them with the target public key Q, the attacker recovered the private scalar d = 123 after exactly 123 sequential attempts.

The recovered private key was then used to reconstruct the ECDH shared secret, derive the AES encryption key and decrypt the ciphertext.

The original message, "HELLO STATISTICS", was recovered without reading the recipient's original private key.

Comparison of the Attacks

The two attacks exploited different weaknesses.

The Caesar statistical attack used linguistic regularities preserved by the substitution cipher. Its effectiveness depended on how closely the sampled text resembled typical English.

The ECC attack instead relied on exhaustive enumeration of a small private-key space. Its success did not depend on plaintext length or language.

Caesar is also vulnerable to exhaustive search because it has only 26 possible shifts.

In contrast, properly generated secp256k1 private keys come from a much larger space of approximately 2^256 possible values.

Generic discrete-logarithm attacks against the full curve require computational effort on the order of 2^128 group operations. Such attacks are computationally infeasible with current practical capabilities.

Security Limitations

The experiments demonstrate that cryptographic security depends on both algorithm design and parameter selection.

The restricted private-key range is an intentional weakness of the educational ECC configuration, not a demonstrated weakness of the secp256k1 curve itself.

Moreover, the ECC hybrid construction is a custom educational demonstration and has not undergone independent security review.

Statistical cryptanalysis also has limitations: short ciphertexts, unusual vocabulary and incorrect language assumptions may reduce its effectiveness.

Final Conclusion

This homework demonstrated how different cryptographic systems can be compared through their encryption procedures, key spaces and statistical properties.

The Caesar cipher is vulnerable because it combines a very small key space with a substitution that preserves linguistic patterns.

The toy ECC-based scheme was successfully attacked because its private-key range was artificially restricted.

The main conclusion is that cryptographic security requires appropriate algorithms, sufficiently large and unpredictable keys, secure implementations and carefully designed protocols.
